# Public preview (Cloudflare Pages)

A sanitized, static build of the Pulse Ops dashboard UI, safe to publish somewhere public. It is
generated by [`scripts/build-public-preview.mjs`](../scripts/build-public-preview.mjs) and never
modifies the real app in place — the canonical `app/`, `next.config.ts`, `vite.config.ts`, dev
server, and Cloudflare deployment are all untouched by this.

## What's different from the real app

The build script copies the whole repo into a throwaway staging directory
(`.public-preview-stage/`, gitignored) and, only in that copy:

- **Deletes `app/api/`.** The preview is served as static files only — it cannot run the route
  handlers that dismiss food/event rows, save job-application stages, or read the phone-location
  forecast. Those routes already refuse any request that isn't from the local dashboard
  (`refuseUnlessLocal` / `isLocalHost`), so nothing here changes their behavior for the real app;
  this just removes code that can't run on static hosting anyway.
- **Replaces `app/queueSnapshot.ts` with [`fixtures/queueSnapshot.ts`](fixtures/queueSnapshot.ts).**
  The real file is committed operational data — weight/body-fat history, real job applications
  with employer names and salary figures, real restaurant and event addresses, a live automation
  queue. The fixture keeps the exact same exported types so every component renders unchanged,
  but every value in it is invented for this preview (`Example Organization`, `Sample Cafe`,
  `Demo Institute`, etc.) — nothing in it is real.
- **Removes the private Google Sheet links** (`sourceLinks` in `app/page.tsx`) — the "Open live
  queue" / "Open sheet" buttons become inert (`href="#"`) instead of pointing at the real,
  privately-shared spreadsheets.
- **Disconnects the live feed** (`app/liveFeedUrl.ts` returns `''`, and the poller no-ops when
  that happens). The real feed is a public, read-only, CORS-locked Cloudflare Worker endpoint
  with no personal fields in its schema, so this isn't a data leak either way — it just stops the
  static preview from making a background network call to the user's personal infrastructure
  every 2 seconds from every visitor's browser.
- **Sets `output: 'export'`** in a throwaway `next.config.ts` ([`next.config.export.ts`](next.config.export.ts))
  so `vinext build` produces static HTML/CSS/JS instead of a Cloudflare Workers bundle.

Everything else — layout, styling, components, copy — is the real app's code, byte-for-byte.

## Building it locally

```bash
npm run build:public-preview
```

Output lands in `public-preview-dist/` (gitignored) at the repo root. Serve it with any static
file server to look at it, e.g.:

```bash
npx serve public-preview-dist
```

`GH_PAGES_BASE_PATH=/<sub-path>` builds for hosting under a sub-path; the Cloudflare Pages deploy
serves from the root, so it leaves this unset.

## Deploying (automatic on every push to main)

[`.github/workflows/deploy-public-preview.yml`](../.github/workflows/deploy-public-preview.yml)
builds this on every push to `main` (and on a manual **Run workflow**), refuses to continue if any
`docs.google.com/spreadsheets` link survived the sanitizing, and deploys `public-preview-dist/` to the
Cloudflare Pages project `leviops-public-preview`: https://leviops-public-preview.pages.dev.
A manual run from a branch other than `main` gets a preview URL, not production.

This repository is a sanitized public mirror. The existing preview uses Cloudflare Pages;
its legacy project name and URL remain unchanged by the product rebrand.

One-time prerequisite: a repository secret `CLOUDFLARE_API_TOKEN` (a Cloudflare API token with
**Account → Cloudflare Pages → Edit**). Until it exists the workflow still builds and checks the preview but
skips the deploy step with a notice.
